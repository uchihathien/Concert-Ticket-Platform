# 1.1: Bảng `booking_proposals` (V0104), record `BookingProposal`, port và adapter Jdbc

**Story ID:** 1.1
**Epic:** 1 — Booking Proposal: AI đề xuất, khách xác nhận
**Slug:** booking-proposals-migration
**Status:** review   <!-- lifecycle: backlog -> ready-for-dev -> in-progress -> review -> done -->

> Owned by planning until `ready-for-dev`. Sized to one dev-day (~2-8h). No story points.

## Story

As a **dev của ai-chatbox-service**,
I want **bảng `booking_proposals` (migration V0104), record `BookingProposal` + enum trạng thái trong `domain/model`, port `BookingProposalRepository` và adapter `JdbcBookingProposalRepository` với đủ phép chuyển trạng thái nguyên tử**,
so that **1.2 (lập đề xuất), 1.4 (xác nhận/huỷ) và 1.6 (hết hạn + metric) cùng dùng một hợp đồng dữ liệu, và mọi ràng buộc nghiệp vụ "một đề xuất mở cho một khu", "chỉ PROPOSED mới được xác nhận" nằm trong SQL chứ không trong đầu từng story**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. Migration `V0104__booking_proposals.sql` tạo bảng `booking_proposals` với các cột `id uuid PK, user_id uuid NOT NULL, chat_session_id uuid NOT NULL, event_slug text NOT NULL, event_session_id uuid NOT NULL, zone_code text NOT NULL, quantity int NOT NULL, unit_price_vnd bigint NOT NULL, total_vnd bigint NOT NULL, status text NOT NULL DEFAULT 'PROPOSED', order_id uuid NULL, order_number text NULL, checkout_url text NULL, payment_expires_at timestamptz NULL, expires_at timestamptz NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), confirmed_at timestamptz NULL`; CHECK `status IN ('PROPOSED','CONFIRMED','EXPIRED','CANCELLED')`, CHECK `quantity BETWEEN 1 AND 6`, CHECK `(status = 'CONFIRMED') = (confirmed_at IS NOT NULL)` và `(status <> 'CONFIRMED' OR order_id IS NOT NULL)`; index `(user_id, status, expires_at)`; partial unique `(user_id, event_session_id, zone_code) WHERE status = 'PROPOSED'`; partial index `(expires_at) WHERE status = 'PROPOSED'`. Flyway chạy sạch trên database rỗng (IT khởi động được context).
2. `domain/model` có enum `BookingProposalStatus {PROPOSED, CONFIRMED, EXPIRED, CANCELLED}` và record `BookingProposal(id, userId, chatSessionId, eventSlug, eventSessionId, zoneCode, quantity, unitPriceVnd, totalVnd, status, order (BookingProposal.Order | null), expiresAt, createdAt, confirmedAt)` với record lồng `Order(orderId, orderNumber, checkoutUrl, paymentExpiresAt)`; có `boolean isOpen(Instant now)` (= `status == PROPOSED && expiresAt.isAfter(now)`); không import Spring/Jackson (ArchitectureTest `domain_thuan_nghiep_vu` xanh).
3. Interface `BookingProposalRepository` trong `domain/port` có đúng các phương thức: `void insert(BookingProposal)`, `Optional<BookingProposal> findById(UUID)`, `int cancelOpen(UUID userId, UUID eventSessionId, String zoneCode, Instant now)`, `boolean cancel(UUID id, UUID userId, Instant now)`, `boolean markConfirmed(UUID id, BookingProposal.Order order, Instant now)`, `int expireOverdue(Instant now)`, `Map<BookingProposalStatus, Long> countByStatus()`; Javadoc ghi rõ mỗi phép chuyển trạng thái là một `UPDATE … WHERE status = 'PROPOSED'` nguyên tử và giá trị trả về nghĩa là gì.
4. `JdbcBookingProposalRepository` (`infrastructure/persistence`, `@Repository`, `JdbcClient`) hiện thực port: `insert` ném `DuplicateKeyException` khi vi phạm partial unique; `markConfirmed` chỉ cập nhật dòng `status = 'PROPOSED'` và ghi `order_id, order_number, checkout_url, payment_expires_at, confirmed_at, status = 'CONFIRMED'`; `cancel` chỉ cập nhật dòng `status = 'PROPOSED'` của đúng `user_id`; `expireOverdue` chỉ đụng `status = 'PROPOSED' AND expires_at <= :now`; `countByStatus` trả đủ bốn khoá (giá trị 0 cho trạng thái không có dòng).
5. IT `JdbcBookingProposalRepositoryIT` (kế thừa `AiChatboxTestBase`) chứng minh: insert → findById khớp từng trường (kể cả `order` null); insert lần hai cùng `(user_id, event_session_id, zone_code)` khi dòng cũ còn PROPOSED ném `DuplicateKeyException`, nhưng sau `cancelOpen` thì insert được; `markConfirmed` trả `true` lần đầu và `false` lần hai; `cancel` của user khác trả `false`; `expireOverdue` đổi đúng dòng quá hạn và không đụng dòng CONFIRMED; `countByStatus` đếm đúng.
6. `AiChatboxTestBase.resetChatbox` liệt kê thêm `booking_proposals` trong lệnh TRUNCATE; test double `InMemoryBookingProposalRepository` có trong `src/test/java/.../support/` tái hiện đúng các hợp đồng ở AC #3 (kể cả ném `DuplicateKeyException` khi trùng đề xuất mở) để 1.2/1.4/1.6 viết unit test không database.
