## Story

As a **dev giao diện khách (web-customer)**,
I want **phản hồi của `POST /v1/chat/agent/support` mang một trường có kiểu `action: ActionCard | null` — thẻ `BOOKING_PROPOSAL` khi lượt vừa lập đề xuất, kiểu `PAYMENT` khai sẵn để endpoint nút Đồng ý (1.4) trả về — với hình dạng JSON phân biệt bằng `kind`**,
so that **giao diện vẽ thẻ Xác nhận/Huỷ hoặc thẻ thanh toán từ dữ liệu có cấu trúc, không bao giờ parse `answer`, và chuỗi VietQR không bao giờ đi qua mô hình (FR-002, NFR-008)**.

## Acceptance Criteria

<!-- LOCKED. Numbered, testable. External dev tools must not edit. -->

1. `domain/model/ActionCard.java` là `sealed interface ActionCard permits ActionCard.BookingProposal, ActionCard.Payment` với `enum Kind { BOOKING_PROPOSAL, PAYMENT, BOOKING_INTENT }` (BOOKING_INTENT chỉ khai, chưa có biến thể) và `Kind kind()`; record `BookingProposal(UUID id, String summary, String eventTitle, Instant sessionStartsAt, String zoneCode, int quantity, long totalVnd, Instant expiresAt)`; record `Payment(UUID orderId, String orderNumber, long totalVnd, String vietQrPayload, String paymentReference, String checkoutUrl, Instant paymentExpiresAt)` (`vietQrPayload`, `paymentReference`, `checkoutUrl`, `paymentExpiresAt` được null); compact constructor kiểm các trường bắt buộc khác null; không import Spring/Jackson (ArchitectureTest `domain_thuan_nghiep_vu` xanh).
2. `application/booking/ActionCards.java` (lớp tiện ích tĩnh) có `ActionCard.BookingProposal proposal(BookingProposal p, EventDetail event)` (tìm suất theo `p.eventSessionId()`, tier theo `p.zoneCode()`; `summary = "{quantity} vé {tierName} · {eventTitle} · {HH:mm ngày d/M/yyyy}"`, bỏ phần giờ nếu `startsAt` null), `ActionCard.Payment payment(PlacedOrder order)` và `ActionCard.Payment payment(BookingProposal confirmed)` (từ `confirmed.order()` + `totalVnd`, QR/reference null); `application/agent/ActionCardView.java` là record phẳng `@JsonInclude(NON_NULL)` với `String kind` + hợp các trường của hai biến thể, có `static ActionCardView of(ActionCard card)` (null → null).
3. `ToolDispatcher.DispatchResult` thành `(ToolOutcome outcome, List<EventRef> events, ActionCard action)`; `of(outcome)` cho `action = null`; thêm `withAction(outcome, card)`; case `PROPOSE_BOOKING` khi `Proposed` trả `withAction(outcome, ActionCards.proposal(proposal, event))`, không kèm `EventRef`; khi `proposed:false` hoặc lỗi → `action = null`. JSON tool cho mô hình KHÔNG chứa `vietQrPayload`/`paymentReference` ở bất kỳ case nào.
4. `AgentReply` thành `(UUID sessionId, String answer, List<String> toolsUsed, ActionCard action)` + constructor phụ ba tham số (`action = null`); `CustomerSupportAgentUseCase.runAgent` giữ `ActionCard` CUỐI CÙNG khác null qua các vòng và trả nó; lượt chuyển người thật, hết vòng, trợ lý không dùng được → `action = null`.
5. `SupportChatController.AskResponse` thành `(UUID sessionId, String answer, List<String> toolsUsed, ActionCardView action)`; JSON có khoá `"action": null` khi không thẻ; `{"kind":"BOOKING_PROPOSAL","id":…,"summary":…,"eventTitle":…,"sessionStartsAt":"…Z","zoneCode":"A","quantity":2,"totalVnd":3600000,"expiresAt":"…Z"}` khi có đề xuất (không có khoá của PAYMENT); `{"kind":"PAYMENT","orderId":…,"orderNumber":…,"totalVnd":…,"vietQrPayload":…,"paymentReference":…,"checkoutUrl":…,"paymentExpiresAt":"…Z"}` khi có đơn; `ChatIdempotency` lưu/đọc lại `AskResponse` kèm `action` không lỗi; bản lưu cũ thiếu `action` đọc được với `null`.
6. `frontend/packages/ts-sdk/src/types/support.ts` có `BookingProposalCard { kind: 'BOOKING_PROPOSAL'; id; summary; eventTitle; sessionStartsAt: string | null; zoneCode; quantity: number; totalVnd: number; expiresAt: string }`, `PaymentCard { kind: 'PAYMENT'; orderId; orderNumber; totalVnd: number; vietQrPayload: string | null; paymentReference: string | null; checkoutUrl: string | null; paymentExpiresAt: string | null }`, `type ActionCard = BookingProposalCard | PaymentCard`, `type ActionCardKind = ActionCard['kind'] | 'BOOKING_INTENT'`, và `AskResponse.action: ActionCard | null`; `pnpm --filter @nexaticket/ts-sdk typecheck` và `pnpm --filter web-customer typecheck` xanh mà không sửa `SupportChat.tsx`.
7. Test: `ToolDispatcherTest` khẳng định `result.action()` là `ActionCard.BookingProposal` đúng `id`/`totalVnd`/`expiresAt`/`summary` sau `proposeBooking` thành công và `null` khi từ chối; `ActionCardsTest` kiểm ba factory (kể cả `startsAt` null, `order()` null → ném); `CustomerSupportAgentUseCaseTest` kiểm `reply.action()` sau lượt đề xuất và `null` sau lượt `escalateToHuman`; `ChatIdempotencyIT` dựng `AskResponse` bốn tham số, round-trip cả hai `kind`, và đọc body cũ thiếu `action`.
